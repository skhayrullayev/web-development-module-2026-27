01 · The field

A page is not an application

Page

A document that already exists. The server hands over a file and the conversation ends.

University news article · a printed menu · your first HTML file next week.

Application

Decides what to send at the moment you ask — reads a database, checks who you are, assembles a response nobody had written down before.

The student portal · your coursework.

Six weeks on the browser, six on the server. That split exists because your coursework is an application, not a page.
Both definitions are hidden. Ask for a definition of each in the students' own words before clicking. Reveal Page first, let it settle, then Application. R reveals both.

02 · The journey

Six stops, six kinds of failure

"The page won't load" is not a diagnosis.

StageWhat failure looks like
DNSCould not resolve host — the name has no address
TCPConnection refused or timed out — nothing is listening
TLSCertificate warning — expired, wrong name, untrusted issuer
Request404 or 405 — wrong path, or right path with the wrong verb
Response500 — your code raised an exception
Render200, blank page — HTML arrived, JavaScript threw
Naming which stop failed is the single most useful habit in this module.

03 · Naming

DNS turns a name into an address

  1. Browser and OS cache — asked recently? Usually yes, and we stop here.
  2. Recursive resolver — your ISP's, or a public one such as 8.8.8.8. It does the legwork.
  3. Root servers — "I don't know udea.uz, but here is who runs .uz."
  4. TLD servers — "Here are the authoritative name servers for udea.uz."
  5. Authoritative server — "udea.uz is 203.0.113.24, cache it for 300 seconds."
Live demo. nslookup udea.uz, then nslookup udea.uz 8.8.8.8. If the answers differ you get a free discussion about caching.

03 · Naming

Records you will actually use

TypeMaps toYou will use it when

AAAAIPv6 addressThe same, on modern hosts

MXMail serverSending registration emails from your app
TTL is why a DNS change "doesn't work yet". The old answer is cached somewhere between you and the root, and it expires on its own schedule. Nothing is broken — you are early.

04 · Verbs

The method is the verb of the request

MethodPurposeSafeIdempotentBody
GETRead a resourceYesYesNo
POSTSubmit data, create somethingNoNoYes
PUTReplace a resource entirelyNoYesYes
DELETERemove a resourceNoYesNo

Safe — changes nothing on the server, so a browser may fetch, prefetch or retry it freely.
Idempotent — sending it five times leaves the server exactly as sending it once.

04 · Verbs

This is a security rule, not a style rule

<a href="/delete?id=7">Delete</a>   ← a GET. Anything that follows links will fire it.

A search crawler, a chat app generating a link preview, or the browser's own prefetcher will send that request without a human deciding to. Row 7 disappears and nobody clicked anything.

Destructive actions go in a POST form. We return to this in week 11, when the same mistake becomes a CSRF vulnerability.
Cold call. "Why is a password never sent with GET?" Four correct answers: browser history, server access logs, the Referer header, shoulder surfing. Name all four.

05 · Answers

Status codes: the first digit is the story

Pick a code

1xx informational · 2xx success · 3xx redirection · 4xx the client was wrong · 5xx the server was wrong.

05 · Answers

401 and 403 are not the same

401

Unauthorized

"I don't know who you are." No valid identity was presented. Send the visitor to the login form.

403

Forbidden

"I know exactly who you are, and you are not allowed here." Show a permission message — do not bounce them back to login.

This distinction is marked in your coursework. Role-based access in week 9 depends on getting it right.

07 · Trust

What the padlock promises

GuaranteeMeaning
ConfidentialityNobody in between can read the traffic
IntegrityNobody can alter it without detection
AuthenticationThe server proved it holds the private key for that domain name
Not includedThat the site is honest. A phishing site can hold a perfectly valid certificate.
"Look for the padlock" is incomplete advice, and you will hear it from users of your own sites.

07 · Trust

The handshake, briefly

  1. Client says hello and lists the cipher suites it supports.
  2. Server replies with its choice and its certificate chain.
  3. Client checks the chain against the roots shipped with the OS, plus the name and the expiry date.
  4. Both sides derive a shared session key. From here the connection is encrypted and symmetric.
Week 12: your Flask app goes behind nginx with a Let's Encrypt certificate. It is free, and a login form on plain HTTP loses marks under the security criterion.
Live demo. Click the padlock and walk the chain: leaf → intermediate → root. If the network allows it, badssl.com has stable expired-certificate pages.

08 · Instruments

Reading a response without a browser

$ curl -I https://udea.uz
HTTP/2 200
content-type: text/html; charset=UTF-8
server: nginx

$ curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://udea.uz
200 0.184s

In the Network panel, five columns carry nearly everything: Name, Status, Type, Size, Time. Sort by Time to find what is slowing your page; filter by Fetch/XHR to see only the calls your JavaScript made.

09 · Toolchain

Git in one minute

git init                          # start tracking this folder
git add index.html                # stage the change
git commit -m "Add landing page"  # record it with a reason
git remote add origin <url>       # point at GitHub
git push -u origin main           # upload

Three states: the working directory is what you edited, the staging area is what you chose to include next, the repository is the permanent history. add moves work from the first to the second, commit from the second to the third.

Not today. Branching lands in week 4. Today's goal is narrow: every student leaves with a repository containing a commit they made themselves.

10 · Checkpoint

Eight questions

Answer before you look at the feedback. A wrong answer you thought about is worth more than a right one you guessed.

Answered 0 of 8

Question 1 of 8

A browser has just received an IP address for udea.uz. What has it not yet established?

DNS answers "where", not "is anyone home". The TCP handshake is what confirms a server is accepting connections on that address and port.

Question 2 of 8

Which is both safe and idempotent?

GET is the only one of the four that changes nothing. PUT and DELETE are idempotent but not safe — repeating them is harmless, but the first one still modified the server.

Question 3 of 8

Your Flask route works in the browser but returns 405 from curl. Why?

405 is Method Not Allowed. The resource exists; the verb is wrong. A route declared methods=['POST'] rejects a plain curl GET.

Question 4 of 8

A logged-in user opens an admin page and receives 403. What should your application do?

403 means the identity is known and insufficient. Sending an authenticated user back to the login form is a common coursework bug — that response belongs to 401.

Question 5 of 8

Which header decides which site a shared server should serve?

One IP address can host hundreds of domains. Host is how the server tells them apart — the mechanism behind nginx virtual hosts in week 8.

Question 6 of 8

Why should "delete account" never be a plain link?

Anything that follows links — a crawler, a chat app building a preview, the browser's prefetcher — fires that GET with no human deciding to. Destructive actions need POST.

Question 7 of 8

A padlock appears in the address bar. What does it not guarantee?

TLS authenticates the domain, not the intentions of whoever registered it. Phishing sites routinely hold valid certificates.

Question 8 of 8

You edited style.css, reloaded, and nothing changed. First thing to check?

Cache-Control means the browser may reuse the old file. Hard-reload, confirm in the Network panel that the request returned 200 and not 304, and only then start editing selectors.
